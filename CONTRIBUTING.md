# Contributing

Thank you for helping improve UCCI. This repository is the reference implementation of a
published method, so two things matter more than anything else: the core must stay faithful
to the paper, and every claim in code, docs and results must be checkable.

## Ground rules

- **Paper-faithful core.** `src/ucci/{signal,calibration,policy,router,metrics,io}.py`
  implement what the paper (arXiv:2605.18796) specifies. Anything the paper leaves open is a
  documented implementation choice, listed in `docs/paper_mapping.md`. Anything beyond the
  paper goes in a separate module or behind an option that is off by default, labelled
  "extension, not in the paper" in its docstring.
- **Cite the paper precisely.** Docstrings cite sections, equations, tables and appendices by
  the arXiv v1 numbering (for example "Section 4.3, Eq. 7" or "Table 2, bottom block").
- **Results come from code.** The paper's own numbers may be quoted only when attributed ("the
  paper reports ..."). Any number presented as a result must be produced by a script in this
  repository, with its inputs.
- **Real references only.** Every external reference (paper, arXiv ID, DOI, URL) must be
  checked before it is added.
- **Style.** Plain, technical prose. No em or en dashes anywhere (code, comments, docs, commit
  messages); use commas, colons, parentheses or two sentences. The pre-commit hook and CI check
  this.

## Development setup

```bash
git clone https://github.com/varunkotte6/ucci
cd ucci
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pre-commit install
```

The `Makefile` wraps every check; pass `PYTHON=.venv/bin/python` (or activate the
environment).

| Command | Runs |
|---|---|
| `make test` | `pytest` (unit tests), the benchmark tests and the doctests |
| `make test39 PY39=/path/to/python3.9` | the unit tests on Python 3.9, the oldest supported version |
| `make lint` | `ruff check .` |
| `make typecheck` | `mypy` (strict, `src/ucci`) |
| `make docs` | `mkdocs build --strict`, then every README and docs snippet |
| `make golden-check` | fails if the golden vectors are out of date |
| `make rust` | `cargo fmt`, `clippy -D warnings`, tests with and without default features, docs, package |
| `make rust-msrv` | the Rust tests on 1.70 (`rustup toolchain install 1.70.0` first) |
| `make bench-smoke` | the CoNLL-2003 analysis on the committed smoke logs, no model needed |
| `make build` | sdist and wheel, `twine check` |
| `make check` | lint, typecheck, tests, golden check and docs |

CI runs the same commands on Linux and macOS for Python 3.9 to 3.13, plus a job with the
minimum dependencies (numpy 1.20 on Python 3.9) and the Rust jobs.

## Tests

- New behaviour needs tests. Prefer exact checks: brute force over all cases for small
  problems, comparison against an independent implementation (scikit-learn for the isotonic
  fit), and hand-computed values.
- Tests must run offline. Tests that need optional packages (torch, transformers, openai,
  matplotlib, scikit-learn, hypothesis) skip cleanly when they are missing.
- The core must keep working on Python 3.9 with numpy 1.20: use
  `from __future__ import annotations`, and no `match` statements or `X | Y` types at runtime.
- `import ucci` must not import any optional dependency.

## Golden vectors and the Rust crate

`tests/golden/*.json` hold inputs and expected outputs generated by `tools/make_golden.py`
from the Python core. `tests/test_golden.py` replays them in Python and `rust/tests/golden.rs`
in Rust, where every float must match bit for bit. After any change to the core's behaviour:

```bash
python tools/make_golden.py                              # regenerate the vectors
(cd rust && cargo test)                                   # the Rust port must still match
(cd rust && UCCI_BLESS=1 cargo test --test golden)        # only if the router writer changed
python -m pytest tests/test_golden.py
```

`make golden` runs the first and third steps. A change that makes Rust and Python disagree
needs the same change in `rust/src`.

## Documentation

The site is MkDocs with Material and mkdocstrings (`mkdocs serve` for a live preview). API
pages are generated from the numpy-style docstrings. `docs/_ext/check_snippets.py` runs every
Python snippet of `README.md` and `docs/` (and the `bash` blocks marked
`<!-- snippet: run -->`), so a snippet that stops working fails CI. Mark code that needs a GPU
or a server with `<!-- snippet: skip (reason) -->`, and code that needs an optional package
with `<!-- snippet: requires package -->`.

## Pull requests

Keep changes focused, describe what changed and how it was tested, and update
`CHANGELOG.md` under "Unreleased". For a change to the method itself, point to the section of
the paper it follows or say explicitly that it is an extension.

## Releases

1. Set the version in `pyproject.toml`, `rust/Cargo.toml`, `CITATION.cff` and `.zenodo.json`,
   and move the "Unreleased" changes under the new version in `CHANGELOG.md`.
2. Tag `vX.Y.Z` on main and push the tag. `.github/workflows/release.yml` checks that every
   version field matches the tag, builds and checks the distributions, publishes to PyPI
   with trusted publishing and creates the GitHub release.
